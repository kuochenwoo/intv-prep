## Scope

Calibrate P1/P2 against the expanded 40-topic and 15-scenario libraries. This work does not implement the deferred voice, study-plan, mock-interview, usage-accounting or export features. Existing cached questions and feedback remain historical records; the changes apply to new requests, without rewriting history.

## Changes

- P1 generation explicitly separates visible code/state/environment from the hidden answer mechanism. Visible constraints must not supply the requested output or explanation. Private opening checkpoints cover only the actual opening question; optional comparisons and optimizations belong in follow-up directions.
- P1 follow-ups accept equivalent natural language, acknowledge explanations already given, narrow for uncertainty and explicitly name a changed condition. P2 follows one main decision in the selected stage and preserves the candidate's stated commit/durability ordering.
- P1 feedback receives only independent candidate answers and the interviewer questions immediately followed by independent answers. It excludes AI-assisted answer text, unanswered prompts and hidden generated directions/checklists. Trusted assistance counts provide disclosure context without giving the grader assisted text as ability evidence.
- After a successful, schema-valid provider response, a local provenance guard forces AI-only feedback to five `missing` dimensions, explicit unassessed evidence, independent-practice advice, and no independent strengths or technical gaps. This is application policy, not a claim that the model obeyed. Mixed histories retain the model's assessment of independent evidence and receive an enforced assistance disclosure. A provider/network/decoding failure still returns an error; the guard does not fabricate a successful request.
- P2 feedback excludes model-authored observations, unsubmitted drafts, private checklists and unanswered prompts. Submitted answers, relevant answered questions and shared design notes remain available.
- P2 prompts distinguish task inputs, explicit illustrative/alternative baselines, arithmetic and conclusions. They recognize explicitly declared uncompressed estimates, permit task-number substitution without falsely alleging missing assumptions, avoid invented compression ratios/benchmarks/prices/instance counts, and distinguish percentile latency from mean processing time.
- New question cache provenance records `deep-dive-v4-calibrated` and `system-design-v2-calibrated`. Existing IDs, cache entries, schemas, drafts, retry states, credentials and interview workflows are preserved.

## Local enforcement and Claude batch (2026-10-15)

Prompt rules alone did not hold in the DeepSeek batches, so the remaining items now have local checks that do not depend on model compliance:

- **P1 answer leakage.** Generation returns private `answerTerms` (2–4 mechanism terms the candidate must supply). A question whose `question`, `background` or `constraints` contains any of them, case-insensitively, fails validation and is regenerated within the existing content retries. Single letters and ASCII terms under four characters are ignored because they occur in code. Questions cached before this field existed have no terms and still load.
- New P1 questions record cache provenance `deep-dive-v5-answer-terms`.
- **P1 checklist scope.** Checklist items the model marks optional, bonus or not required move to `followUpDirections` after generation; a checklist made only of such items is rejected.
- **Summary counts.** P1 and P2 feedback whose summary counts stages or dimensions (for example "only two stages", "the other seven dimensions", "其余七个维度") is rejected and regenerated.
- **P2 stage coverage.** The feedback context includes `discussedStages`, and the application appends the stages that actually have submitted answers to the summary, using the UI stage labels.
- **P2 gaps.** Each gap is returned with the answered interviewer question it comes from. Gaps whose question does not match an answered question (exact, contained, or at least 70% shared character pairs after normalization) are dropped. The stored feedback format is unchanged.
- **P2 unexamined stages.** If no answer was submitted in the requirements or estimation stage, that dimension is set to `missing` with an explicit not-assessed explanation.

## Closeout implementation (2026-10-15)

The reviewed guards were insufficient: a correct question citation could accompany unrelated criticism, stage-based overrides erased genuine evidence supplied in another stage, and an empty `answerTerms` bypassed new-question checks. These are substantive findings.

- `FreshQuestion` separates strict generation from legacy cache loading. New questions require 2–4 distinct effective answer terms; omitted, empty, duplicate or too-short terms fail within existing bounded content retries. Old records still load. Optional checkpoints move before fresh validation and review.
- P2 no longer forces ratings from stage labels. An exact question citation establishes only provenance, never semantic relevance; fuzzy matching is removed.
- New P1 questions and P1/P2 feedback receive a separate real model review against the same scoped input. Review checks synonymous hints, checklist scope, gap relevance even with exact citations, cross-stage evidence, AI provenance, unassessed-versus-uncertain ratings and summary consistency. A rejection receives one repair attempt with explicit actionable instructions; repeated rejection returns a translated quality error. Network/decoding failures remain errors, never local successes.
- Reviews use the same selected provider/model with no extra history, credentials or source code. Reviewer JSON is suppressed from the UI stream. Author requests retain streamed previews, provisional until review completes. No database migration or key change is introduced.
- Review is a separate invocation of the same model, not an independent provider or a truth guarantee. These checks increase latency and API usage: normally one author plus one reviewer call, at most two proposals, each subject to three bounded content-decoding attempts. Follow-ups/reference-answer calls retain existing behavior.
- Cache provenance is `deep-dive-v6-reviewed` / `system-design-v3-reviewed`; old sessions are not rewritten.

Tests cover legacy compatibility, strict new terms, cross-stage evidence, critique propagation, repeated rejection and review transport failure. Fixtures are explicit offline tests, not live acceptance. `content/evals/calibration-closeout.json` adds deliberately flawed hints, unasked gaps with exact citations and unassessed dimensions rated uncertain, plus a cross-stage answer.

The user explicitly approved the Claude closeout batch: the original 16 interview operations, one cross-stage feedback operation and three direct reviewer probes. Normally this is 31 model calls, at most 53 with repair, up to 159 HTTP attempts including bounded content retries. The first operation exhausted its two semantic attempts and failed honestly; its output log is preserved at `review/calibration-closeout-initial-failure.log`. That version lacked review tracing, so the rejection details cannot be reconstructed. After adding explicit repair instructions and opt-in traces, the same approved inputs continue under a shared cap of 147 further HTTP attempts, reserving a conservative 12 for the failed operation. The counter covers author calls, reviews, repairs and decoding retries; exhausting it fails the evaluation.

### Corrections found during closeout

The first combined reviewer falsely treated private answer terms as visible, applied question anti-leak rules to feedback, and questioned trusted assistance counts because assisted text had intentionally been removed. A dedicated reviewer system now has separate question and feedback policies; it does not inherit the author/interviewer role. It explicitly preserves required missing dimensions, allows explanatory practice advice, trusts local assistance metadata and allows empty strengths/gaps. Earlier failure logs and verdicts remain in `review/`.

Human review also caught a model-approved metrics summary falsely claiming assistance and calling communication unassessed while rating it good. Summaries are now **derived locally from validated ratings and recorded independent/assisted counts** in both languages. P2 appends actual discussed stage labels. The free-form model summary is discarded before review and persistence; the reviewer evaluates the actual application summary plus the model's detailed evidence, ratings, strengths, gaps and advice. The brittle summary-count rejection was removed; legacy summaries still load. No stage label determines a rating. The reviewer is explicitly told not to treat input-number substitution alone as requirements analysis, and not to demand unasked extensions or fabricated strengths.

The earlier accepted feedback is archived at `review/calibration-closeout-before-canonical-summary.json`. The refreshed batch reuses previously tested follow-ups and regenerates feedback with the final summary policy. The final review recheck revisits all accepted question/feedback outputs and the three adversarial probes under the dedicated review policy. All continuation attempts share the same persisted counter and 147-attempt cap. These iterations use only the already-approved scripted material.

### Final repair and presentation rules

Repair requests now contain both `qualityReviewIssues` and the exact `previousProposal`; tests assert both arrive together. Previously a stateless author could fix one critique while regenerating unrelated mistakes. The final rule preserves correct fields and changes only flagged defects and associated inconsistencies. There is still at most one automatic repair; a failed operation is retained as a failure and an explicit evaluation retry consumes the same global request budget.

`missing` means **insufficient independent evidence**, including both unasked content and a question answered with “I do not know.” It does not mean the question was necessarily unasked or a technical error was demonstrated. The UI and derived summaries now use that wording in both languages. Evidence must distinguish these cases. `uncertain` remains for a disputed technical judgement. Explicit illustrative capacity baselines, unmeasured thresholds and a pending regional RPO are not grading deductions; unasked details belong in practice advice.

Final rechecks use the exact production context builders, so private grading checklists, unanswered questions, AI-only P1 text and evaluation expectations cannot become grader evidence. Deterministic summary projection in report artifacts is explicitly marked; actual real-provider ratings, evidence and gaps are preserved. Before-projection reports and rejected proposals remain archived. These projections are application presentation policy, not fabricated model answers or fake successful calls.
